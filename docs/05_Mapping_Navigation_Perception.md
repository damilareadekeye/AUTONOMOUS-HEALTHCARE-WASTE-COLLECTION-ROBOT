## 2. Run it (four terminals; run `source ~/hcw_ws/scripts/env.sh` in each)

```bash
# 1  simulation (Gazebo server, no window: see the speed note in section 6)
scripts/clean_sims.sh
ros2 launch hcw_bringup sim_clinic.launch.py          # add gui:=True for the Gazebo window, rviz:=True for RViz
# 2  navigation on the saved map (start about 45 s after 1)
ros2 launch hcw_navigation navigation.launch.py
# 3  tag detection
ros2 launch hcw_perception apriltag.launch.py
# 4  drive to places and check tags
ros2 run hcw_navigation go_to collection_A
ros2 run hcw_perception tag_monitor --collect 6
ros2 run hcw_navigation go_to collection_B collection_C storage home
```
The robot must start at the home spot (8.0, -31.7): Nav2 sets AMCL's start pose to it
(`amcl.initial_pose` in `config/nav2_params.yaml`). Restart the simulation before restarting Nav2,
otherwise the robot and AMCL disagree about where the robot is.

## 4. How the map was made

1. The clinic's own walkable corridor graph (Open-RMF `nav_graphs/0.yaml`, level L1) gives safe
   waypoints. `map_clinic` drives Nav2 along it in steps of 3 m while SLAM Toolbox builds the map.
   (Steps matter: Nav2 rejects goals that lie outside the part of the map built so far.)
2. The map is saved with `nav2_map_server map_saver_cli`. Its origin is shifted by the robot's
   start pose (8.0, -31.7) so that map coordinates equal world coordinates.
3. Speckle was removed from the saved image: occupied pixel groups shorter than 1.5 m (stray scan
   points in the open hall) were turned into free space. The raw map is not kept; re-run `map_clinic`
   to regenerate.
4. Alignment was checked by plotting the clinic's consulting-room doors and graph points on the map:
   they fall on the wall openings and corridors.

Covered: the west wing (Clinic A rooms and corridor), the north corridor, and part of the
north-east hall. Not mapped: the east wing and the middle of the building (Clinic B side).

## 6. Findings and fixes (read before changing things)

1. **Doors:** the clinic world has about 140 door and lift models that Open-RMF opens with a plugin.
   Without it they stay shut and block the doorways. `world_builder.py` removes every inline model
   that has a joint.
2. **Gazebo window slows the simulation about 10x** (real-time factor 0.1 with the window, 0.96 without,
   with Nav2 and tag detection running). The launch therefore opens no window by default; use
   `gui:=True` or run `gz sim -g` in another terminal when you want to look.
3. **`BasicNavigator.waitUntilNav2Active()` resets AMCL to (0, 0)** because it publishes a default initial
   pose. Always call it with `localizer='bt_navigator'` (done in `go_to.py` and `map_clinic.py`).
4. **Planning through unknown space** (`allow_unknown: true`, the Nav2 default) sent the robot into the
   unmapped east side. It is set to `false`.
5. **Behaviour-tree timeouts:** `default_server_timeout` 20 ms made goals fail at the very end on a loaded
   machine; it is 2000 ms now.
6. **Inflation radius** 0.7 m is too wide for 2 m corridors: 0.45 m now.
7. **Composition:** `navigation.launch.py` sets `use_composition: False`; with composition the Nav2 container
   did not finish starting.
8. **Tag textures:** an emissive material turned the tag into a white square. Textures are referenced with
   `model://` paths. Tag size 0.30 m because the TurtleBot camera is only 320 x 240.
9. **Tag check:** `ros2 topic echo --once` reads one message, often an empty one. Use
   `tag_monitor --collect`.
